# Huawei AR730 Router Easy Manager

**أداة سطح مكتب بواجهة رسومية لإدارة التحكم بالوصول على راوتر Huawei NetEngine AR730 — عبر SSH، دون معرفة أي أمر من أوامر VRP.**

[![License: Apache 2.0](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](LICENSE)
[![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)](https://www.python.org/downloads/)

> 🇬🇧 [English README](README.md)

موظف الاستقبال لا ينبغي أن يعرف `aaa` و `local-user` و `cut access-user` كي يُدخل طابعة إلى
الشبكة. هذه الأداة تحوّل تلك العمليات إلى أزرار، وتفرض قواعد الترتيب التي يشترطها الجهاز
صامتاً، وتتحقق من كل كتابة بإعادة قراءة الإعداد، وتحفظ محلياً **لمن** يعود كل عنوان ماك — وهو
ما لا يستطيع الراوتر تخزينه.

تأتي مع **محاكي راوتر كامل يعمل بلا شبكة**، فتستطيع تقييمها والتدرّب عليها قبل أن تلمس أي
جهاز حقيقي.

## ما الذي تفعله

| التبويب | الوظيفة |
|---|---|
| **الأجهزة الموثوقة** | إضافة وإزالة عناوين ماك من القائمة البيضاء مع اسم وصفي. الجهاز المسجَّل يدخل الشبكة **بلا صفحة تسجيل دخول** — مناسب للكمبيوترات والطابعات والكاميرات ونقاط الوصول. |
| **حسابات البوابة** | إنشاء وحذف حسابات Captive Portal، وتغيير كلمات السر ومجموعات الصلاحيات. هذا هو المناسب للهواتف. |
| **المتصلون الآن** | من هو متصل، بأي IP وماك، وحالته. مع زر لفصل أي جلسة، وزر لتوثيق جهاز متصل مباشرة. |
| **مجموعات الصلاحيات** | عرض المجموعات ورقم الـACL المرتبط بكل واحدة وعدد الأعضاء. |
| **تحويل المنافذ NAT** | عرض وإضافة وتعديل وحذف تحويلات TCP الثابتة. يتحقق النموذج من تعارض المنفذ الخارجي، ومسار الجهاز الداخلي، وعدم وضعه خطأً في شبكة WAN؛ ويعيد قراءة الراوتر بعد كل تغيير، مع استرجاع القاعدة القديمة إذا لم يثبت التعديل. |
| **البحث** | تصفية حيّة في كل الجداول بالماك أو الاسم أو الحالة أو المجموعة أو الـIP. مطابقة الماك تتجاهل الفواصل. |
| **سجل الأوامر** | كل أمر أُرسل وكل رد جاء من الراوتر. |

**الواجهة بالعربية والإنجليزية**، مع انعكاس كامل للتخطيط في العربية (RTL) لا مجرد ترجمة نصوص.

## جرّبه قبل أن تلمس الشبكة

```bash
python ar730_qt.py --demo
```

بلا `paramiko` وبلا أي اتصال شبكي. المحاكي يفرض قواعد الجهاز الحقيقي: يرفض الترتيب المقلوب،
ويرفض كلمة سر تساوي اسم المستخدم، ويرفض `irreversible-cipher`، ويسأل `[Y/N]` عند الحفظ.
شريط العنوان يكتب **DEMO** كي لا يلتبس الوضعان. هذا هو المكان الذي يتدرّب فيه الموظف الجديد.

## التثبيت

راجع أيضاً [دليل التثبيت الأول والتحديث](INSTALL.md).

### Windows وmacOS — بلا Python

تنشر GitHub Releases نسخاً مستقلة لويندوز x64 وmacOS بمعالجي Apple Silicon وIntel؛ لا يحتاج
المستخدم إلى تثبيت Python أو أي مكتبات.

في **PowerShell على Windows**، ثبّت أو حدّث بأمر واحد:

```powershell
irm https://raw.githubusercontent.com/AFZ92/huawei-ar730-router-easy-manager/main/scripts/install.ps1 | iex
```

وفي **Terminal على macOS**:

```bash
curl -fsSL https://raw.githubusercontent.com/AFZ92/huawei-ar730-router-easy-manager/main/scripts/install.sh | bash
```

يختار كل أمر الملف المناسب للنظام ويتحقق من SHA-256 بمقارنته مع `SHA256SUMS.txt` قبل التثبيت.
وعند بدء التطبيق يفحص GitHub Releases في الخلفية: إذا نُشر إصدار أحدث مناسب للجهاز تظهر رسالة
برقم الإصدار المثبّت والجديد وزر لفتح صفحة التنزيل. تُحفظ الإعدادات وبيانات الأجهزة والسجل خارج
مجلد البرنامج، لذلك لا يمسّها التحديث.

**لأول مرة:** افتح الطرفية المناسبة أعلاه، الصق أمراً واحداً فقط، ثم افتح **AR730 Manager** من
قائمة Start في Windows أو Applications في macOS. لا تحتاج إلى Python. ستجد نفس أوامر التثبيت
ورقم الإصدار المثبّت في صفحة «الدليل والدعم» داخل التطبيق.

### التطوير من المصدر

يحتاج **Python 3.9 أو أحدث**.

```bash
git clone https://github.com/AFZ92/huawei-ar730-router-easy-manager.git
cd huawei-ar730-router-easy-manager
pip install -r requirements.txt
python ar730_qt.py
```

تشغّل ملفات `run.sh` و`run.bat` واجهة Qt الرسمية مباشرةً.

## مزامنة البيانات بين أجهزة الإدارة (Firebase)

اختر **Firebase أساسي** مرة واحدة بعد إعداد الاتصال. بعدها يحفظ التطبيق كل تعديل محلياً
ويزامنه تلقائياً في الخلفية، ويجلب تغييرات الأجهزة الأخرى عند بدء التشغيل وكل خمس ثوانٍ
عندما لا تكون عملية على الراوتر قيد التنفيذ. لا يلزم الضغط على زر رفع أو تنزيل. تبقى بيانات
الاتصال واللغة وكلمات المرور خاصة بالجهاز؛ تتم مشاركة سجلات الأجهزة والأسماء والحسابات
والسجل والإعدادات الشبكية المشتركة فقط.

1. استخدم مشروع Firebase نفسه وقاعدة **Cloud Firestore `(default)`** على جميع الأجهزة.
2. من **الإعدادات** استورد ملف service account ثم اختر **Firebase أساسي** واحفظ الإعدادات.
   اعتماد الخدمة يستخدم صلاحيات **IAM**، وليس Firestore Rules. يجب أن يستطيع قراءة وكتابة
   `ar730_manager/shared_state` وإنشاء وقراءة مستندات `ar730_manager_revisions`.
3. حدّث التطبيق على **كل الأجهزة** ثم أعد تشغيله؛ الإصدارات القديمة قد تستبدل قاعدة البيانات
   كاملةً ولا تطبق حماية المزامنة الجديدة.

طريقة Web API Key مع Firebase Authentication تبقى مدعومة. لهذه الطريقة فقط، استخدم قواعد
مقيدة بحساب المزامنة (استبدل `SYNC_ACCOUNT_UID` بمعرّف الحساب):

```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /ar730_manager/shared_state {
      allow read, write: if request.auth != null && request.auth.uid == 'SYNC_ACCOUNT_UID';
    }
    match /ar730_manager_revisions/{revision} {
      allow read, create: if request.auth != null && request.auth.uid == 'SYNC_ACCOUNT_UID';
      allow update, delete: if false;
    }
  }
}
```

كل جهاز يحتفظ بآخر نسخة أقرّت المزامنة حفظها، ويُدمج تغييراته فقط مع النسخة السحابية الحالية.
الكتابة مشروطة برقم مراجعة Firestore؛ إذا عدّل جهاز آخر النسخة أثناء الإرسال، يعيد التطبيق
القراءة والدمج بدلاً من الكتابة فوقها. أول تشغيل يدمج البيانات المحلية والسحابية تلقائياً.
علامات الحذف تمنع إعادة سجلات أو حقول محذوفة من نسخة قديمة.

إذا عُدّل الحقل نفسه بالتزامن، تبقى القيمة التي التزمت بها السحابة أولاً، وتُحفظ النسخة الأخرى
للاسترجاع. تُحفظ لقطات المدخلات والنسخة الناتجة في `ar730_manager_revisions` قبل الكتابة؛
لا يحذف التطبيق هذه النسخ تلقائياً. توجد كذلك نسخ محلية في مجلد `backups` وملف
`ar730_devices.json.bak`. يعرض الشريط الجانبي حالة المزامنة وأي تعارض محفوظ.

عند انقطاع الشبكة أو فشل الصلاحيات أو امتلاء التخزين، يبقى التعديل على القرص ويُعاد الإرسال
تلقائياً، حتى بعد إعادة التشغيل. إذا تعذّر إنشاء نسخة الاسترجاع، تتوقف الكتابة السحابية بأمان.
تستخدم الملفات المحلية كتابة ذرية، ويُحفظ مؤشر المزامنة مع البيانات في الملف نفسه.
يحتوي السجل النشط على أحدث 2000 حدث؛ الأحداث الأقدم تبقى في نسخ الاسترجاع، ولا يُقصّ السجل
المحلي أثناء العمل دون اتصال. لا توجد حماية مطلقة من حذف النسخ الاحتياطية يدوياً أو تلف القرص
أو الحساب السحابي، ولذلك احتفظ أيضاً بنسخة احتياطية مستقلة لبياناتك.

لا تُرفع بيانات اعتماد Firebase أو كلمة مرور SSH أو كلمة MAC المشتركة. الوضع **محلي فقط**
يعطّل المزامنة. التفاصيل التقنية للكتابة المشروطة موثقة في
[مرجع Firebase](https://firebase.google.com/docs/firestore/reference/rest/v1/projects.databases.documents/patch).

## قواعد يفرضها البرنامج تلقائياً

كل واحدة منها سلوك حقيقي في VRP كلّف أحدهم وقتاً:

1. **ترتيب الأوامر إلزامي** — `service-type` ثم `password` ثم `user-group`.
2. **كلمة سر الماك مشتركة ولا تساوي اسم المستخدم.**
3. **`cipher` لا `irreversible-cipher`.**
4. **المجموعة إلزامية** — حساب بلا مجموعة يحصل على وصول **غير مقيّد**.
5. **تغيير الصلاحيات لا يسري على جلسة قائمة** — لذلك يُتبع كل تغيير بأمر `cut`.
6. **التحقق بعد كل كتابة** — يُعاد قراءة الإعداد للتأكد، ولا يُستنتج النجاح من غياب الخطأ.
7. **الحفظ تلقائي** بعد كل تغيير ناجح.

## الإلغاء لا يعني الحذف

عند إلغاء جهاز يُحذف من الراوتر فعلاً ويفقد الوصول فوراً، لكنه يبقى في السجل المحلي بحالة
«ملغى» مع التاريخ والسبب، بلون رمادي. فيبقى لديك أثر لمن كان لديه وصول ومتى سُحب.

## إعداد مهم

`mac_shared_password` في تبويب الإعدادات **يجب أن تطابق حرفياً** ما هو مضبوط في الراوتر:

```
mac-access-profile name m_wl
 mac-authen username macaddress format without-hyphen password cipher <القيمة>
```

إن اختلفت، لن يدخل أي جهاز موثوق وسترى `Local username or password is wrong`. هذا هو السبب
الأشيع لمشكلة «وثّقت الجهاز ولم يتصل».

## التطبيق المكتبي

واجهة Qt هي التطبيق الرسمي الوحيد لإدارة الراوتر. ثبّت المتطلبات وشغّل وضع
التجربة أو الوضع الحقيقي من نفس البرنامج:

```bash
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python ar730_qt.py --demo
```

ولتشغيل الاختبارات دون راوتر:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python harness/run_qt_test.py
```

الاختبارات تستعمل راوتر AR730 وهميًا يتكلم VRP، وتغطي الواجهة الكاملة بلا شاشة
وبلا عتاد.
