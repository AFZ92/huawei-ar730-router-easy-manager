# Built-in captive portal (portal local-server)

This file covers how the AR730's built-in portal behaves, how to customise it, and the AFZ
Systems login page in [`afz-portal/`](afz-portal/). It is based on work against the production
router on 2026-09-15. CLI replies are in
[`../router/captures/04-portal-sftp.txt`](../router/captures/04-portal-sftp.txt), and the command
list is section 5 of [`../router/command-reference.md`](../router/command-reference.md).

## How it is wired

```
portal local-server ip 10.0.255.1          (LoopBack1)
portal local-server http port 8080
portal local-server server-source all-interface
portal-access-profile name p_portal
 portal local-server enable layer3
authentication-profile name p_portal_only
 portal-access-profile p_portal
 access-domain portalusers portal force
```

- Portal accounts are `local-user NAME service-type web` in domain `portalusers`, authenticated by
  `local_auth`.
- `display portal local-server`: authentication `chap`, protocol `http`, session-timeout `8(h)`.
- The Mac can reach `http://10.0.255.1:8080/` directly, so **pages can be inspected read-only with
  `curl`** without touching the router configuration.

> ⚠️ **`http acl N` (web-management ACL) also filters this portal server.** Any client outside
> the ACL gets no portal page. Keep `http acl` unset, and test from a phone that is not a
> management device. See [lessons-learned L13](../router/lessons-learned.md#L13).

## What the router serves

### Default state (no `load`)

Pages are generated by the firmware; none of them are on `flash:`.

| URL | Result |
|---|---|
| `/` | **404**. Use `/index.html`. |
| `/index.html` | 200, frame page: logo, background, `[中文]` link, and an iframe to `/login.html` |
| `/login.html` | 200, the login form (English); `/cn/index.html` and `/cn/login.html` are the Chinese versions |
| `/custom/custom.js` | generated from the configuration (show the logo, open welcome/policy pop-ups) |
| `/custom/page.html`, `/custom/policy.html` | the loaded `page-text` / `policy-text` file, served as `text/html; charset=utf-8` |
| `/custom/logo.png`, `/custom/background-1.jpg`, `/custom/ad.png` | the loaded images |
| `/auth_success.html` | 200, **filled in by the firmware** for an online client (see below) |
| `/hasonline.html`, `/logout.html` | a plain GET gives **500** `Internal Server Error` (21 bytes): these are dynamic replies, not files |

Every response carries `Cache-Control: no-cache, no-store, must-revalidate`,
`X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`,
`Content-Security-Policy: object-src 'self'` and `Strict-Transport-Security`.

### After `portal local-server load flash:/X.zip`

- The router serves **only the files inside the zip**. Everything else, including `login.html`
  and `custom/*` when absent from the zip, returns **404**.
- A zip containing only `index.html` gave a blank page after a successful login, because the
  redirect to `auth_success.html` hit a 404.
- Files are served **statically**. In our uploaded `auth_success.html` the fields
  `HiddenUserName`, `HiddenUserIP` and `HiddenLoginTime` came back **empty**. In the firmware's own
  page they contain `internet`, `10.0.21.254` and `1789481970`; its script even hard-codes
  `UserName.value = "internet"`, which shows the page is rendered per user.
  - So a custom page cannot show the client's IP.
  - Username and login time can only be remembered in the browser by the login page.
  - Caveat: we did not confirm that the Mac was portal-online at the moment of that check.
- From the Mac, `POST /logout` returned **404** with the custom zip loaded. It is **not yet known**
  whether the router still ends the session in that case.

## Login contract (copied from the firmware's `login.html`)

```
POST http://10.0.255.1:8080/login
Content-Type: application/x-www-form-urlencoded

username=<≤65 chars>&password=<≤128 chars>&RedirectUrl=<from ?RedirectUrl=>&anonymous=DISABLE&anonymousurl=&checkbox=on
```

- **Browser type:** non-Apple browsers submit the form normally (`target="_top"`). Apple devices
  (`navigator.platform` contains `Mac`, or an iOS user agent) submit with XHR, and the result depends
  on the reply:
  - **Success:** `xhr.status == 200` and `xhr.responseURL` contains `auth_success.html`. Go to
    `responseURL`.
  - **Already online:** the reply text contains `User Has Been Online` or `用户已经在线`. The
    firmware redirects to `hasonline.html`.
  - **Anything else:** the reply HTML replaces the page. The wrong-password reply has **not been
    captured yet**.
- **RedirectUrl:** the firmware reads it from `top.location.href` after `RedirectUrl=` (up to 200
  chars). It appends it to the form action as `?RedirectUrl=` and puts it in the hidden field.
- **Logout:** the firmware's success page posts `LogoutForm` to `http://10.0.255.1:8080/logout`.

## Customisation options

### A. Built-in options: low risk, all dynamic data still works

| Command (system-view) | File requirement |
|---|---|
| `portal local-server logo load flash:/logo.png` | jpg/png, **591×80** px |
| `portal local-server background-image load flash:/bg.jpg` | jpg/png, **1366×768** px (or `default-image1`) |
| `portal local-server ad-image load flash:/ad.png` | jpg/png, **670×405** px |
| `portal local-server background-color #0A6E5C` | `#RRGGBB` |
| `portal local-server page-text load flash:/welcome.txt` | text file; UTF-8 Arabic displays correctly |
| `portal local-server policy-text load flash:/policy.txt` | text file |

- **Reply:** each load answers with `Info: Load web file successfully.` and a warning that the
  setting is lost if the file is deleted and the router reboots. **Keep the files on flash.**
- **Pop-up limitation:** the built-in page opens the welcome text in a **pop-up**, and browsers
  block that. So "the welcome text does not appear" even though it loaded. The policy opens from its
  link.
- **Fixed English labels:** labels such as "User name", "Login" and "REGISTERED USER" cannot be
  changed this way.
- **Removal (❓ not yet run):** `undo portal local-server page-text load`, and likewise for the
  other options.

### B. A full custom page (`portal local-server load`): full design, loses firmware data

Upload a flat zip with every page the firmware may redirect to, then load it (details below).
**Rollback:** `undo portal local-server load` (✅ returns the built-in pages). Loading or unloading asks `this operation will affect online user, continue?[Y/N]` when the portal is in use.

## The AFZ Systems page (`afz-portal/`)

Arabic by default (RTL), with an English toggle remembered in `localStorage`. Welcome and terms text
are inline instead of pop-ups, and the layout is mobile-first.

| File | Role |
|---|---|
| `index.html` | The login form, following the contract above: XHR for Apple, a normal POST otherwise. The login button stays disabled until the terms checkbox is ticked. It stores `afz_user` and `afz_time` in `localStorage` just before submitting. `build.sh` also copies it to `login.html`. |
| `auth_success.html` | Keeps the firmware field names (`HiddenUserName`, `HiddenUserIP`, `HiddenLoginTime`) so that values appear if the router ever fills them. Otherwise it falls back to URL parameters and then `localStorage`. A row with no value is hidden, and the IP row usually is. Logout posts to `/logout` in a hidden iframe, then after 1.5 s shows `logout.html`. |
| `hasonline.html` | "This account is already online". |
| `logout.html` | "You have logged out", with a link back to login. |
| `build.sh` | Produces `build/portal_afz_<version>.zip`, which is git-ignored. |

The server address `http://10.0.255.1:8080` is **hard-coded** in `index.html` and
`auth_success.html`. Change it there if `portal local-server ip/port` changes.

### Deploy (the user runs these)

```
docs/portal/afz-portal/build.sh v3            # on the Mac
sftp admin@10.0.20.1                          # SFTP root is flash:/
put build/portal_afz_v3.zip
bye
```
```
system-view
portal local-server load flash:/portal_afz_v3.zip
return
display portal local-server
```

- **Upload under a new name each time.** Never overwrite the zip the router is currently using.
- **No `save` until the checklist passes.** An unsaved load is undone by a reboot or by
  `undo portal local-server load`.
- **Cleanup:** after `save`, delete old zips and unused test files (`welcome.txt`, `policy.txt`,
  `logo.png`) from flash, but only if no `portal local-server …` line still references them.

### Test checklist

1. Log in from a phone that is not a trusted device. The success page appears, and the name and
   time are shown.
2. Tap **Log out**, then open any website. **Is the internet really cut?** This is the key open
   question: the page shows "logged out" either way.
3. Enter a wrong password and capture what appears, since that reply is still unknown.
4. Log in on a second device with the same account and check the "already online" message.
5. Open a normal `http://` site to be redirected, log in, and confirm that "Continue to the requested
   page" works.
